What works now

Each of these has been tested against the real database, not simulated.

Reporting a fault by QR code

Working

Scanning a code on a wall opens a page that already knows which room it belongs to, and the report is filed against that room. The reporter gets a real reference number they can quote. No account needed.

Printable QR codes for every room

Working

An administrator can add a building and room, then generate and download a QR code to print and mount. Codes that no longer match a real room now fail clearly instead of sending someone into a broken form.

The electrician directory

Working

Searchable by area, specialisation, availability and verification status. Filters are held in the web address, so a filtered list can be shared or bookmarked. It is empty until the first electricians register.

Certificates of Compliance

Record only

An electrician can complete and digitally sign a certificate, and it is permanently recorded against their profile with a reference anyone can verify. The PDF document itself is not generated yet.

Receipts

Record only

Itemised receipts are stored and can be signed by both the client and the electrician, each from their own account. PDF output is still to come.

Accounts, sign-in and permissions

Working

Sign-in is connected and the private areas of the site are genuinely protected — an unauthorised visitor is now turned away rather than quietly let through, which was previously the case.

The security issue, in plain terms

What we found: when the database was first created, every table was left open to the public. Anyone who visited the website could have read every user's name, email address and phone number, viewed all receipts and certificates, and even deleted records.

Why it happened: the tool used to build the database does not switch on access restrictions by default, and the hosting platform publishes tables automatically. Neither is wrong on its own; the gap sits between them.

What we did: access is now denied by default on every table, and the fix is recorded so it applies automatically to any future copy of the system. We confirmed it by attempting to read the data from outside, the way an outsider would — every attempt was refused.

Exposure: the gap was closed before any real customer data was entered and before the site was published, so we have no reason to believe anything was accessed.

Not built yet

Stated plainly, so the current state is not over-read.

Assigning work to an electrician

Not started

The system can already represent a job from assignment through to completion, but there are no screens for it. Today a reported fault cannot yet be handed to anyone. This is the largest remaining gap.

PDF documents and email delivery

Not started

Certificates and receipts exist as records but cannot yet be sent or printed.

Notifications

Not started

Nobody is told when a fault is logged, assigned, or completed.

Payments and subscriptions

Not started

Plans are modelled in the system but no payment provider is connected.

Automated NTA verification

Manual

An administrator marks an electrician as verified by hand. There is no live lookup against the NTA database.

What comes next in order

Each phase is useful on its own, and the order is deliberate — later phases depend on earlier ones.

  1. Put real information in

    Register the first electricians, set up the rooms for one pilot building, and print its QR codes.

    Until this happens the directory is empty and nothing can be tested realistically. It needs no further development work.

  2. Close the loop from fault to finished job

    Build the screens to assign a reported fault to an electrician, track it through to completion, and let the client rate the work.

    This is what turns a reporting tool into a service. The groundwork is already done, so it is screens rather than foundations.

  3. Make the paperwork real

    Generate proper PDF certificates and receipts, and email them to clients automatically.

    Compliance paperwork is a core reason electricians would pay for this, and it is currently the weakest link.

  4. Keep people informed

    Email and SMS alerts when a fault is logged, assigned, or completed.

    Without this, someone has to keep checking the site for anything to happen.

  5. Prepare for paying customers

    Connect a payment provider for subscriptions, then test and monitor the system properly before opening it to the public.

    Deliberately last: charging for something is only worth building once the thing being charged for is complete.

Decisions we need from you

  • Which site should we pilot? We need one real building to install QR codes in and a handful of electricians willing to be the first users.
  • Is manual NTA verification acceptable at launch? Automating the lookup is a significant piece of work and depends on what access the NTA will grant. Checking by hand would let us launch sooner.
  • Which payment provider? This affects phase five and is worth deciding early, as it influences how subscriptions are handled.
One thing to keep in mind: the system currently runs on the development machine against a live hosted database. It has not been published to a public web address yet, so there is nothing to visit — that step comes with phase five.
